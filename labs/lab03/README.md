**Тема:** Прикладні бібліотеки Python для побудови веб-застосунків  
**Дисципліна:** Програмування скриптовими мовами

**Варіант:** 9 — Облік часу опрацювання повідомлень  
**Стек:** Python 3.10+, FastAPI, Pydantic 2, SQLite (модуль `sqlite3`,
без ORM), Ruff

## Предметна область

Сервіс обліку тривалості опрацювання повідомлень про події безпеки.
Кожен запис — одне вимірювання: скільки хвилин тривала перевірка
повідомлення. Категорія визначає джерело повідомлення, `status` — стан
перевірки вимірювання. Дані навчальні й не описують реальну
інфраструктуру.

| Параметр | Значення |
| --- | --- |
| Одиниця вимірювання (`unit`) | `minutes` |
| Поріг (`threshold`) | `15.0` |
| Тип `value` | `float`, не менше 0, без `NaN` і нескінченності |
| Статуси | `new`, `in_progress`, `done` |

Категорії:

| id | name |
| --- | --- |
| 1 | `siem` |
| 2 | `helpdesk` |
| 3 | `monitoring` |

Поріг `15.0` задано в `config.py` і наведено в описі API; обмеженням
значень він не є (верхня межа `value` у схемі — максимальне число
`float`).

## Запуск

Усі команди виконуйте з кореня репозиторію, в активованому віртуальному
середовищі.

1. Встановлення залежностей:

   ```bash
   pip install -r requirements.txt
   ```

2. Первинне заповнення бази навчальними даними (3 категорії, 8 записів
   в одній транзакції; повторний запуск виводить повідомлення, що дані
   вже заповнені, і нічого не змінює):

   ```bash
   python -m labs.lab03.seed
   ```

3. Запуск веб-сервера API:

   ```bash
   uvicorn labs.lab03.main:app --reload --host 127.0.0.1 --port 8000
   ```

4. Автодокументація Swagger UI: <http://127.0.0.1:8000/docs>
   (OpenAPI-схема: <http://127.0.0.1:8000/openapi.json>).

Окремо створити лише таблиці (без даних) можна командою
`python -m labs.lab03.database`; сервер також створює відсутні таблиці
під час запуску, не перезаписуючи дані.

## Маршрути

| Метод і маршрут | Призначення | Відповідь |
| --- | --- | --- |
| `GET /ping` | Перевірка доступності | 200 |
| `GET /student` | ПІБ, група, варіант | 200 |
| `GET /categories` | Категорії за зростанням `id` | 200 |
| `POST /categories` | Створення категорії | 201, 409 (дубль назви) |
| `DELETE /categories/{category_id}` | Видалення порожньої категорії | 204, 404, 409 (є записи) |
| `GET /records` | Список із фільтрами | 200 |
| `GET /records/{record_id}` | Один запис | 200, 404 |
| `POST /records` | Створення запису | 201, 404 (категорія), 409 (дубль `code`) |
| `PUT /records/{record_id}` | Повна заміна запису | 200, 404, 409 |
| `DELETE /records/{record_id}` | Видалення запису | 204, 404 |
| `POST /records/bulk` | Атомарне пакетне створення (1–100) | 201, 404, 409 |

Усі некоректні тіла запитів і параметри дають `422`. Параметри
`GET /records`: `category_id`, `status`, `min_value`, `q` (буквальний
підрядок у `title` з урахуванням регістру), `limit` (1–100, типово 20),
`offset` (≥ 0, типово 0); фільтри поєднуються через `AND`, результат
відсортовано за `id`. Неіснуюча `category_id` у фільтрі дає порожній
список.

## Приклади запитів

Приклади виконуються по черзі на базі після `python -m labs.lab03.seed`.

### Службові маршрути та читання

```bash
curl -i "http://127.0.0.1:8000/ping"
curl -i "http://127.0.0.1:8000/student"
curl -i "http://127.0.0.1:8000/categories"
curl -i "http://127.0.0.1:8000/records?category_id=1&status=new&limit=5&offset=0"
```

Очікувано: `200 OK`; `/ping` повертає `{"status":"ok"}`, фільтр повертає
`V09-01` і `V09-04`.

### Створення запису

```bash
curl -i -X POST "http://127.0.0.1:8000/records" \
  -H "Content-Type: application/json" \
  -d '{"code":"V09-TEST","title":"Навчальне вимірювання","category_id":1,"value":7.5,"status":"new"}'
```

Очікувано: `201 Created`; у відповіді передані поля, створений `id` (для
свіжої бази — `9`) і `"category_name":"siem"`. Далі `9` — це отриманий `id`.

### Повна заміна запису

У `PUT` передаються всі п'ять змінюваних полів:

```bash
curl -i -X PUT "http://127.0.0.1:8000/records/9" \
  -H "Content-Type: application/json" \
  -d '{"code":"V09-TEST","title":"Навчальне вимірювання","category_id":2,"value":20.0,"status":"done"}'
```

Очікувано: `200 OK`, `id` не змінився, `"category_name":"helpdesk"`.

### Видалення запису

```bash
curl -i -X DELETE "http://127.0.0.1:8000/records/9"
```

Очікувано: `204 No Content`; повторний виклик — `404 Not Found`.

### Пакетне створення

Успішний пакет — обидва записи зберігаються в одній транзакції:

```bash
curl -i -X POST "http://127.0.0.1:8000/records/bulk" \
  -H "Content-Type: application/json" \
  -d '[{"code":"V09-BULK-1","title":"Пакетний запис 1","category_id":1,"value":4.0,"status":"new"},{"code":"V09-BULK-2","title":"Пакетний запис 2","category_id":3,"value":16.5,"status":"in_progress"}]'
```

Очікувано: `201 Created` і список із двох `RecordRead`.

Відкат транзакції: перший елемент новий, другий має `code`, який уже є в
базі (`V09-01`):

```bash
curl -s "http://127.0.0.1:8000/records?limit=100" | grep -o '"id"' | wc -l

curl -i -X POST "http://127.0.0.1:8000/records/bulk" \
  -H "Content-Type: application/json" \
  -d '[{"code":"V09-ROLLBACK","title":"Перший елемент","category_id":1,"value":4.0,"status":"new"},{"code":"V09-01","title":"Дублікат коду","category_id":2,"value":5.0,"status":"new"}]'

curl -s "http://127.0.0.1:8000/records?limit=100" | grep -o '"id"' | wc -l
curl -s "http://127.0.0.1:8000/records?q=ROLLBACK"
```

Очікувано: `409 Conflict` із повідомленням
`Дублювання коду в пакеті або в базі даних`; кількість записів до й після
запиту однакова, `V09-ROLLBACK` у базі відсутній (`[]`). Якщо другий
елемент посилається на неіснуючу категорію (наприклад, `"category_id":99`),
відповідь — `404`, і жоден запис також не зберігається.
